# AI 宣传查证所：录屏操作与讲解脚本

本文件是录制计划，不表示视频已经录好。以当前页面和实际返回结果为准；录制后记录日期、案例和真实视频链接。

## 录制前

1. 在本项目运行 `npm start`；若 4191 已由本项目使用，直接打开页面。
2. 打开 <http://127.0.0.1:4191/>，确认元宝搜索已配置。配置有效就不重复验证。
3. 用 macOS `Shift + Command + 5` 选择录制网页区域，确保不包含密钥、其他私人窗口和无关通知。需要旁白时由录制者选择麦克风。
4. 建议录制一段 3—5 分钟完整演示，另保留三个真实案例的小片段或截图。联网等待可以加速，但要注明，且保持同一问题的查询与结果连续。

## 主演示顺序

| 阶段 | 实际操作 | 讲解重点 |
|---|---|---|
| 开场 | 展示首页与问题输入区 | “一句免费宣传，放到我的使用场景里，条件可能不同。” |
| 真实新查询 | 填公开产品问题、具体需求和官方域名，点“开始查证” | 示例问题可用“Notion 免费版 AI 是否承诺每月固定免费次数？”；需求填“每月使用 100 次，不购买付费计划”。这里只提问，不预设答案 |
| 查询结果 | 展示真实三轮搜索、请求 ID、时间和来源；打开一条关键官方原文 | 搜索摘要只是线索；零命中不等于证伪。结果与预期不同也如实保留 |
| AI 深查 | 点“复制 AI 深查任务”，在仅含本项目的 WorkBuddy 任务中加载 Skill，实际阅读来源并形成证据卡 | 网页没有独立大模型接口，不能讲成点击按钮就自动完成 AI 判决。若此段使用之前保存的结果，标注“已保存深查结果” |
| 条件卡亮点 | 打开 `/?case=01`，在条件卡中改变“我的具体使用需求”，点“按现有证据重新判断” | 展示已核实条件如何影响适用判断。明确这是本地重算，不是再次搜索 |
| 不确定性 | 选“证据不足”的需求例子或超出现有条件的需求 | “无法支持的结论保留未知，新增事实需要再查。” |
| 导出 | 导出 Markdown 或 JSON，打开文件展示问题、需求、来源、请求记录和复核状态 | 未真正人工复核就保持“尚未人工复核”，不能为视频效果虚假勾选 |

若临时网关失败，保留失败画面并补录恢复后的真实成功流程。案例回放用于展示已保存证据，片头应写清“真实查询记录回放”，不能冒充现场新发起。

## 放进 GitHub

- 主视频建议命名 `ai-claim-investigator-demo.mp4`；小视频可放 `docs/videos/`。
- 大视频优先作为同一仓库的 Release 附件，README 放实际附件链接，不写不存在的视频地址。
- 在 `docs/videos/README.md` 记录真实文件、时长、录制日期、现场查询/回放类型和字幕说明。
- 上传后从仓库页面实际点开观看/下载；需供评委直接查看时使用无需额外申请权限的链接。
- 提交比赛前按表单要求另上传三份真实提问材料；GitHub 中有视频不等于参赛表单已经上传或正式提交。
